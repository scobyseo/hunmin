# IBus engine — real-use evaluation checklist (issue #292)

Two ways to drive it, both without changing the desktop's input method:

- `tools/ibus-real-use.sh desktop` — opens `gnome-text-editor` as a **normal
  window on your current desktop** with a private IBus daemon and the hunmin
  engine. This is the one to use for ordinary "does it feel right" evaluation.
  Pass another app name to override, e.g. `... desktop kate`.
- `tools/ibus-real-use.sh portable` — opens the same app in a nested Xephyr
  window with its own display, for an isolated reproduction.

Both extract the built `.deb` artefacts into a private prefix under the repo,
so no sudo or system install is needed, and the desktop's fcitx5 and session
bus are untouched. Type on your own keyboard; do not evaluate from the CI
harness. For a system install (sudo required) use `tools/ibus-real-use.sh install`.

## 1. Registration and selection

- [ ] The script prints `IBus engine: hunmin` without an error.
- [ ] `ibus list-engine` (in that session) lists `hunmin - Hunmin`.

## 1b. Layout (the maintainer's default is 신세벌P2)

The script defaults to `sin3-p2` via `HUNMIN_IBUS_LAYOUT`; the banner prints the
active id. To check another one:
`HUNMIN_REALUSE_LAYOUT=sin3-p2-basic tools/ibus-real-use.sh desktop`
(also `sin3-p2-yet`, or `dubeolsik` for comparison).

- [ ] The banner says `layout: sin3-p2`, and the live key log's first line says
      `"layout":"sin3-p2"` — that meta is the layout the engine actually
      resolved, not the env id it was asked for.
- [ ] `한/영` produces a trace line with `"base":0`, `"raw":65514` (Alt_R,
      0xffea) and `"consumed":true`, and the next Latin letter appears as Latin.
      Two 2026-11-22 bugs were fixed to make this true: (1) the D3 layout seam
      passed a NULL Latin id, killing the toggle — pinned by
      `engine-d2-ibus-ui`'s `LayoutOverrideKeepsTheLanguageKeyAlive`; (2) under
      XKB `us` the physical key is Alt_R (0xffea), not Hangul (0xff31). Both
      spellings are accepted by default as of 2026-11-22 (FE13); the D2
      regression toggles with each keyval in turn.
- [ ] `kfcQ` → `각` — P2 cho/jung/jong keys are on separate physical positions.
- [ ] `jk1` → `ㅇµ` (the tier-A golden for this exact sequence) — no dubeolsik
      fallback is silently being used.
- [ ] `u/ameibwk/f ` → `동해물과 ` — the long sin3-p2 cultural case composes
      byte-exact (keys from `tests/e2e/cases.tsv`, generated by
      `tools/jamo-keytable.py`); if this fails, note the first wrong syllable.
- [ ] Shift+P / Shift+K / Shift+J produce `;`, `"`, `'` (P2 symbol tier), while
      the bare `; " '` keys emit jamo — do not assume ASCII identity.

## 2. Composition and delivery (dubeolsik examples unless §1b is being run)

| Keys to type | Expected | What this checks |
|---|---|---|
| `dkssuds ` | `안녕ㄴ ` in the buffer | per-syllable commit plus the declined space reaching the client |
| `gksrmf ` | `한국어 ` | normal sentence composition |
| `d` (stop mid-word) | preedit `ㅇ` visible, not committed | preedit is shown while composing |
| `dkssud` then BackSpace | `안녕` minus the last jamo | backspace takes the last unit, not a byte |
| `q` in Hangul mode | `ㅂ` (dubeolsik) | layout data is loaded, not a hardcoded map |

## 3. Hanja / host lookup table

- [ ] `kfs` then `F9`: the IBus panel draws a lookup table (this is the host's
      table, not a hunmin-owned window — the own-window gate does not apply).
- [ ] Down/Page_Down moves the highlight; Return commits the selected Hanja.
- [ ] `Escape` closes the table and typing resumes in the same word.

## 4. Language switch (FE13)

- [ ] Pressing the Han/Eng key once switches to Latin; the committed word stays.
- [ ] Typing letters in Latin mode produces ASCII, not jamo.
- [ ] Pressing it again returns to Hangul.

## 5. Failure signals to report (do not "fix" silently)

- Preedit that never appears even though text commits on space.
- A key that the engine should decline (space, Enter) being swallowed.
- The engine process dying on F9 or on a deep candidate page.
- A long Hangul sentence inserting text in the wrong order.

Record what you observed next to each box, including the target distro and IBus
version (`ibus --version`). A negative result is a finding; the ruling is the
maintainer's.
