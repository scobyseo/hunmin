# hunmin 0.1.0 — GitHub Release notes

## What 0.1 ships

- `libhunmin.so` — the engine (C99, stable ABI). Layouts/symbol tables are data files.
- `hunmin-sim` — the trace simulator (engine, no IME framework).
- `fcitx5` addon (`hunmin` addon + input method, `hunmin.conf`).
- Android IME (`InputMethodService` + JNI, debug `assembleDebug` only).
- All layout/compose/hanja/idioms/krdict data files.

## Version-string convention (ruled 2026-10-12, issue #9)

The release is `0.1.0` everywhere: `CMakeLists.txt`, `debian/changelog`, and the git tag.
Android keeps its build-phase suffix: `versionName` is `0.1.0-p5` (IME) and
`0.1.0-p5.5` (keymaps APK). Those `-pN` suffixes are the Android build phase, not a
different release.

## How a user gets 0.1

```sh
# engine + fcitx5 addon (from a clean checkout, rebuild the .deb)
dpkg-buildpackage -us -uc -b

# or download the prebuilt .deb from this release
dpkg -i hunmin_0.1.0_amd64.deb
```

Android (debug build only; there is no release-grade signing key yet — the APK
builds signed with a throwaway key, see below):

```sh
frontends/android/gradlew assembleDebug
```

## Verification

- `cmake -B build && cmake --build build` — engine + hunmin-sim + fcitx5 addon.
- `ctest --test-dir build -j16 --output-on-failure` — the suite. (`ctest -N`
  *lists* tests and runs none of them, so it is not the gate; the registered
  count is configuration-dependent, so state yours rather than quoting one.)
- `python3 tools/docs-lint.py --build-dir build` and
  `python3 tools/wiki-lint.py` — 0 errors each.
- The `.deb` ships `libhunmin.so.0.1.0`, `fcitx5/libhunmin.so`, `hunmin-sim`,
  `/usr/share/fcitx5/{addon,inputmethod}/*.conf`, and the full data tree. Check
  with `dpkg -c ../hunmin_0.1.0_amd64.deb`.
- The release APK is **signed with a throwaway key**, not a release key: the
  keystore resolves from `HUNMIN_RELEASE_STORE`, else `local.properties`, else a
  generated one (ruled 2026-10-13, issue #1). It installs and runs; it is not a
  signature to publish under this release. `apksigner verify` is the check.
- The step-by-step procedure, including the local gate, is
  [`tests/manual-checklists/release-0.1.md`](../tests/manual-checklists/release-0.1.md).
